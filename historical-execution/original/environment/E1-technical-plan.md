# E1 technical qualification decisions

Only artificial sequences from the E0-frozen qualification input file are used. The biological run matrix remains unexecuted. Models are loaded sequentially in float32, with four CPU intra-op threads, one inter-op thread, batch size one, inference/evaluation mode and no KV cache, padding or truncation. Selected residuals are captured at block outputs, including the last block before model-wide normalisation. All summaries use float64.

The first ProFam CPU load was rejected because its checkpoint contains `model.token_embedder.weight`, a key absent from the released model class. Inspection established exact tensor equality to `model.model.embed_tokens.weight`. The adapter now accepts only this verified duplicate; missing keys or other unexpected keys still fail. The original failed report and log are retained. No forward pass occurred in that attempt.

The first complete CPU ProFam qualification used 15 passes. Repeated identical inputs were bitwise reproducible, but C-extension comparisons changed normalised earlier states by up to 1.49e-6, exceeding the repeat-only floor of 1e-7. That standalone CPU result is recorded as failing that envelope. The prespecified MPS qualification used 15 further passes. MPS extension comparisons were exact, and the measured long-input forward times were lower than CPU. Final eta follows the existing protocol: max(1e-7, 10 times the largest repeat or CPU–MPS normalised per-residue discrepancy). It is calculated from those discrepancies, not fitted to the causal comparison or a biological outcome.

Additional diagnostics are declared before their execution: one ProFam MPS Q3 pass will record driver allocations because process RSS alone does not measure GPU allocation; one ESM Q1/Q1_C pair on the selected backend will check that the bidirectional adapter sees a future extension. These are frozen artificial strings. The reserve explicitly allows extra mapping/visibility tests charged to the unused passes. Planned totals are 31/40 ProFam passes and 20/30 ESM passes (9 CPU + 9 MPS repeats and 2 diagnostic forwards), with zero warmups and zero E2 passes. MPS ESM will be selected only after measured CPU concordance and timing; no smaller model is substituted.

The diagnostic cases cannot change eta, the primary layer, panel or interpretation rule. Raw arrays, failed attempts, process logs and source snapshots are retained. A separate verification pass will recompute discrepancies and costs from those arrays and logs before the E1 receipt is written.
